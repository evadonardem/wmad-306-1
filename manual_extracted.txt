1. Introduction
Welcome to the Barangay Sports League API project! In this exercise, you will build a fully functional REST
API backend for a community basketball league management system — the kind of system a real barangay
sports coordinator might use. The API handles authentication via Laravel Sanctum and manages leagues,
seasons, teams, players, game schedules, results, and standings.
By the end of this project you will be able to:
• Set up and configure Laravel Sanctum for token-based API authentication.
• Design and implement a relational database schema with multiple related models.
• Build RESTful API endpoints using Laravel controllers and resource routes.
• Apply belongsTo, hasMany, and belongsToMany Eloquent relationships including pivot data.
• Implement business logic validation and scoped queries per authenticated user.
• Build computed summary endpoints for standings and leaderboards.
What You Will Build
• A full authentication system (register, login, logout) using Sanctum tokens.
• CRUD endpoints for leagues, seasons, teams, and players.
• A game scheduling system that validates team eligibility within a season.
• A result and player stats submission system that updates game status.
• A standings endpoint that computes win-loss records per team.
• A player leaderboard that aggregates stats across all completed games.

5. Eloquent Relationships
Define the following relationships in your models. These are the foundation of your API — getting them right
first will make building controllers much easier.
5.1 Relationship Map
User
hasMany --> League
hasMany --> Season
hasMany --> Team
belongsToMany --> Player (pivot: jersey_number)
hasMany --> Game
hasOne --> GameResult
hasMany --> PlayerStat
5.2 belongsToMany with Pivot
The relationship between Team and Player is many-to-many. A team has many players, and a player can be
on many teams (across different seasons). The pivot table stores the jersey number which belongs to that
specific team assignment.
// In Team model
public function players(): BelongsToMany
{
return $this->belongsToMany(Player::class, 'player_team')
->withPivot('jersey_number');
}
// In Player model
public function teams(): BelongsToMany
{
return $this->belongsToMany(Team::class, 'player_team')
->withPivot('jersey_number');
}
5.3 Game Foreign Keys
The games table has two foreign keys pointing to the same teams table: home_team_id and away_team_id. In
your Game model, define both as separate belongsTo relationships with explicit foreign key names.
public function homeTeam(): BelongsTo
{
return $this->belongsTo(Team::class, 'home_team_id');
}
public function awayTeam(): BelongsTo
{
return $this->belongsTo(Team::class, 'away_team_id');
}

6. Authentication with Laravel Sanctum
All endpoints except register and login must be protected with the auth:sanctum middleware. Sanctum issues a
plain-text token on login which the client must send in subsequent requests via the Authorization header.
6.1 Auth Endpoints
Method Endpoint Description
POST /api/register Register a new admin user. Returns user + token.
POST /api/login Authenticate and receive a Sanctum API token.
POST /api/logout Revoke the current token. Requires auth. [auth]
6.2 Token Flow
On a successful login, your controller should call createToken() on the authenticated user and return the plain
text token in the response. The client stores this token and sends it with every subsequent request.
// In AuthController@login
$user = User::where('email', $request->email)->first();
if (! $user || ! Hash::check($request->password, $user->password)) {
return response()->json(['message' => 'Invalid credentials'], 401);
}
$token = $user->createToken('api-token')->plainTextToken;
return response()->json(['token' => $token, 'user' => $user]);
6.3 Protecting Routes
Wrap all protected routes in the auth:sanctum middleware group in your routes/api.php file.
// routes/api.php
Route::post('/register', [AuthController::class, 'register']);
Route::post('/login', [AuthController::class, 'login']);
Route::middleware('auth:sanctum')->group(function () {
Route::post('/logout', [AuthController::class, 'logout']);
Route::apiResource('leagues', LeagueController::class);
Route::apiResource('leagues.seasons', SeasonController::class);
// ... remaining routes
});
Postman Tip: After login, copy the token from the response. In Postman, go to the Authorization tab of your request,
select Bearer Token, and paste the token there. All requests in this collection will now include it.

8. Step-by-Step Implementation
Note: Complete tasks in order. Each task builds on the previous. Test every endpoint in Postman or Insomnia before
moving on to the next task.
Task 1 — Project Setup & Sanctum
Create a new Laravel project and install Sanctum. Run migrations to generate the default users table.
• Run php artisan install:api to scaffold Sanctum.
• Verify that routes/api.php has been generated.
• Confirm the sanctum configuration file exists in config/.
Task 2 — Migrations
Create all nine migrations listed in Section 4. Run them against your database to generate the schema.
• Create migration files using: php artisan make:migration create_leagues_table
• Add all columns and foreign key constraints as specified in the schema.
• Create the player_team pivot table migration manually — it is not a model migration.
• Run: php artisan migrate
Task 3 — Models & Relationships
Create all eight Eloquent models and define the relationships as shown in Section 5.
• Generate models: php artisan make:model League (repeat for each model).
• Define all hasMany, belongsTo, and belongsToMany relationships.
• Add withPivot('jersey_number') to the Team-Player relationship.
• Define both homeTeam() and awayTeam() in the Game model with explicit FK names.
Task 4 — Authentication Endpoints
Build the register, login, and logout endpoints. Use Laravel's Hash facade to verify passwords and Sanctum's
createToken() to issue tokens.
• Create AuthController with register(), login(), and logout() methods.
• Return the plain text token and user data on successful login.
• On logout, call $request->user()->currentAccessToken()->delete().
• Test all three endpoints in Postman before continuing.
Task 5 — Leagues & Seasons
Build the Leagues and Seasons CRUD endpoints. Scope all league queries to the authenticated user so one
admin cannot access another admin's leagues.
• In LeagueController, always scope queries: $request->user()->leagues()->...
• Use route model binding for all show(), update(), and destroy() methods.
• Seasons are nested under leagues — use the league's relationship to create/list them.

Task 6 — Teams & Players
Build the Teams endpoints. The most important endpoint here is adding a player to a team — this uses the
pivot table.
• To add a player: $team->players()->attach($playerId, ['jersey_number' => $request->jersey_number])
• To remove a player: $team->players()->detach($playerId)
• When showing a team, eager-load players with their pivot data: $team->load('players')
Task 7 — Game Scheduling
Build the game scheduling endpoint. Include the following validation logic before creating a game:
• Both home_team_id and away_team_id must belong to the same season.
• A team cannot play against itself (home_team_id !== away_team_id).
• New games default to status: scheduled.
Task 8 — Game Results & Player Stats
Build the result and stats submission endpoints.
• When a result is submitted, create a GameResult record and update the game's status to done.
• The stats endpoint accepts an array of player stat objects and bulk-inserts them.
• A game must have status: done before stats can be submitted.
Task 9 — Standings
Build the standings endpoint. For each team in the season, compute wins and losses from completed game
results.
• A team wins a game if their score (home or away) is higher than the opponent.
• Return an array of team objects with wins, losses, and games_played.
• Sort descending by wins.
// Hint: Load completed games for the season
$games = $season->games()->where('status', 'done')->with('result')->get();
// Iterate each team and tally their wins/losses
// Check if team was home or away in each game
Task 10 — Player Leaderboard
Build the leaderboard endpoint. Aggregate total points per player across all completed games in the season
and return the top 10.
• Join player_stats through game_results and games filtered by season_id.
• Group by player_id and sum the points column.
• Return the top 10 players with their name and total_points.
Tip: Use Eloquent's withSum() or a raw DB::select() with GROUP BY and ORDER BY. Both approaches are acceptable.

9. Key Concepts Deep-Dive
9.1 Sanctum Token Authentication
Concept Method What it does
Issue token createToken('name')->plainTextToken Returns a string token to send to the client
Get user $request->user() Returns the authenticated User model
Revoke token currentAccessToken()->delete() Deletes only the current token (logout)
Protect route middleware('auth:sanctum') Returns 401 if no valid token is present
9.2 belongsToMany with Pivot Data
The player-team relationship is many-to-many. The pivot table player_team stores extra data (jersey_number)
that belongs to the relationship itself, not to the player or team individually. Always use withPivot() so Eloquent
loads the extra column.
Operation Method Example
Attach player attach($id, $pivot) $team->players()->attach($id, ['jersey_number' =>
7])
Detach player detach($id) $team->players()->detach($playerId)
Read pivot ->pivot->jersey_number $player->pivot->jersey_number
9.3 Scoping Queries to the Authenticated User
All league queries must be scoped to the authenticated user. This ensures one admin cannot read, edit, or
delete another admin's data. Always retrieve leagues through the user relationship, never through the League
model directly.
// WRONG - fetches leagues from any user
$league = League::findOrFail($id);
// CORRECT - only fetches leagues belonging to auth user
$league = $request->user()->leagues()->findOrFail($id);

Exercise 1 — Season Summary Stats (8 points)
Add a GET /api/seasons/{id}/summary endpoint that returns aggregated statistics for the season: total games
played, total games scheduled (not yet played), top scoring team (highest total points across all games), and
total points scored across all games in the season.
Scoring Rubric:
• Endpoint returns total games played and games remaining correctly [2 pts]
• Top scoring team is computed from game results [2 pts]
• Total points across all games is computed correctly [2 pts]
• Response returns 404 with a clear message if season has no completed games [2 pts]
Exercise 2 — Game Validation Rules (8 points)
Strengthen the game scheduling endpoint by adding additional business rule validations. The endpoint should
reject a game if: a game between the same two teams already exists in the season (regardless of home/away
order), or a team already has a game scheduled on the same date.
Scoring Rubric:
• Returns 422 if the same matchup already exists in the season [2 pts]
• Matchup check is order-independent (Team A vs B = Team B vs A) [2 pts]
• Returns 422 if either team already has a game on that date [2 pts]
• Error response includes a descriptive message identifying the conflict [2 pts]
Exercise 3 — Player Profile Endpoint (9 points)

position, a list of all teams they have played for (with season name and jersey number), career totals (total
games played, total points, total assists, total rebounds), and their personal best game (most points in a single
game).
Scoring Rubric:
• Teams list includes season name and jersey number from pivot [2 pts]
• Career totals are correctly aggregated across all seasons [2 pts]
• Personal best game returns the correct game and point total [2 pts]
